# 在原生平台验证构建，保留更新所需的签名身份

已采纳。适用于 GitHub Actions、发布脚本与测试工具。

Tauri 的 Rust 测试和 Clippy 构建会引用前端产物，因此各原生任务先构建 dist。Windows 专用 FFI 和 MSVC 下的 bundled SQLite 需要 Windows runner 验证。Tauri 提供运行时，应用只直接启用所需的 Tokio 同步功能。开发构建保留应用本身的调试信息，依赖省去这部分信息以减少磁盘用量。

Bun 直接导入未编译的 store 时需要替代 rune 函数，浏览器交互测试则运行编译后的 Svelte。测试用单独的 tsc 配置检查 Bun 环境及其 ES2023 API。涉及防抖的取消测试在同一任务中发送输入、回车和 Esc，避免慢机器提前完成查询而改变测试条件。时间格式断言接受不同 ICU 版本在 AM/PM 前使用的空白。密钥检测测试在运行时构造合成样本，以免样本被仓库的凭据扫描器当作凭据。原生 QA 使用隔离的应用身份，退出监听后才恢复私人剪贴板。

版本脚本同时支持 BSD 和 GNU sed，仅改清单顶层版本；README 下载文件名直接从目标版本生成，可修正已有偏差。Prepare Release 要求事先提交发布说明并使用可触发下游标签工作流的 RELEASE_PAT。正在执行的同标签发布不中途取消。构建操作固定到经验证的提交，升级时验证整条发布流程。

macOS 构建复用同一张自签名证书，使系统可在更新后识别相同的辅助功能授权身份。构建任务自己配置钥匙串，避免构建期间自动锁定，并信任自签名根，让 Tauri 能找到有效签名身份。证书私钥与备份留在版本库之外。自签名没有 Apple 公证，首次打开仍会出现 Gatekeeper 提示。发布名称保持为版本标签。校验草稿的令牌需要能查看草稿，校验器只调用读取接口；相同附件只验一次，替换附件后 ID 会变化，缓存中的内容也须验签。

第三方技能由锁文件记录并在本地安装，仓库自有的 delete-comment 单独纳入版本控制。维护者通过 `bun run lint:comments` 检查手写源文件、测试、工作流和配置。每条历史例外按文件和原文匹配，删除例外后同时收紧基线；现有两条属于 Cargo 自动生成的锁文件头。
