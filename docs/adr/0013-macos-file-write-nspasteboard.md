# 0013 macOS 文件写回直接使用 NSPasteboard

- 状态：已采纳

## 背景

arboard 的 `file_list` 会规范化每个路径，并丢弃无法 `stat` 的路径。macOS 26（Tahoe）还有两个行为：

1. pasteboard 服务会核对写入进程能否访问每个 URL 指向的文件，没有权限的条目被静默丢弃，`writeObjects` 仍返回 true。实测桌面上的文件写入后剪贴板里没有条目，`/Users/Shared` 下的文件有一个条目且可以粘贴。
2. 先打开文件会弹出一次性的“文件与文件夹”授权（桌面、文稿、下载）；授权后写入可以通过核对。从终端启动的进程继承终端的授权，所以只有从访达启动时才会失败。

## 决定

- `paste::write_file_list` 直接向 NSPasteboard 写入 NSURL。
- 写入前逐个打开文件以触发授权，不检查打开结果。无法授权的路径（例如其他应用的容器，需要完全磁盘访问权限）由写入后的核对发现。
- 写入后核对剪贴板里实际保留的条目，数量不符就返回错误，不改写成路径文本。
