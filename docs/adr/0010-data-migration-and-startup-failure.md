# 0010 数据目录迁移与启动失败

- 状态：已采纳

## 决定

- 迁移在备份和替换期间一直持有 `state.storage` 锁。这段时间的采集等待这把锁，拿到锁时写入的已经是新数据库，不丢记录，也不写进旧库。
- 旧连接关闭后才删除旧数据库文件，因为 Windows 不允许删除仍被打开的文件。
- 检查目标目录是否可写时，用带 UUID 的文件名独占创建。固定文件名会覆盖并随后删除用户恰好同名的文件。
- 启动时如果 SQLite 判定数据库损坏，就把数据库和 `-wal`、`-shm`、`-journal` 移到 `.corrupt-<uuid>` 备份，再新建空库；其他错误直接返回，应用退出。`initialize_storage_core` 不依赖 `AppHandle`，通知通过闭包传入，便于单元测试。
- 存储或剪贴板监听无法初始化时，release 构建的 `panic = "abort"` 会让应用直接崩溃，用户看不到原因。`spawn_fatal_alert` 在后台线程显示说明对话框后退出，因为 `setup()` 要先返回，事件循环才能显示对话框。显示前先销毁所有 webview 窗口：隐藏的 webview 加载后会立即调用命令，这时没有 `AppState`，读取 State 会 panic。
