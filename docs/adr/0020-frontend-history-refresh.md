# 0020 前端历史刷新与搜索请求

- 状态：已采纳

## 决定

- `clipboardStore` 由 QuickBar 窗口在 onMount 时初始化。设置窗口导入同一个单例但不初始化，不读取历史，也不订阅事件。
- 初始化时先订阅事件再查询。历史加载期间到达的复制事件先记下，加载完成后回放到结果上。
- 历史初始化和追加分页使用各自的请求序号。重置分页只让进行中的追加请求失效，不取消初始加载。
- 无论是否在搜索，历史请求结束时都清除自己的加载状态：搜索只管理 `isSearchPending`，加载中途开始的搜索不会替它清除 `isLoading`。
- 静默搜索在原位刷新同一查询的结果（例如复制后某行的时间戳变了），不切换 pending 状态，否则每次后台刷新都会让搜索图标闪一下。每次给 `searchQuery` 赋值前都会推进请求序号，所以 `isCurrent` 成立就说明 `searchQuery` 仍是这次请求的查询。
- 前台搜索失败时清除结果，不把旧查询的结果留在新输入下面；静默刷新失败时保留仍然有效的结果。
- 复用进行中的搜索请求时同时比较查询词和分类。切换分类会发出新请求，旧请求的结果随请求序号失效。
- 分类筛选的链接判断由后端按完整内容计算，随每行返回 `isLink`。搜索结果只带命中词附近的摘要，摘要可能不以 `https://` 开头，前端不能据此判断链接。
