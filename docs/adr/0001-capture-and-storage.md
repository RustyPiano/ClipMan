# 每次剪贴板变化最多保存一条记录

已采纳。适用于 `clipboard.rs`、`paste.rs`、`storage.rs`、`migration.rs`、`settings.rs` 和 `commands.rs`。

## 选择代表格式

访达复制文件时还会提供名称文本和图标。监听器依次尝试文件列表、文本及附带的 HTML、图片。这样能保留文件身份，还能避免无谓地解码位图。HTML 超出容量时仍保留合规的纯文本。暂停期间不读取剪贴板，也不推进标记。恢复后的第一次采集仍可与暂停前的记录去重。

采集时先读取前台应用，再分派耗时的图片工作。忽略应用和自身复制仍推进去重标记，避免下一次复制与过期内容比较。每个应用每次启动只生成一次 64px 图标，下次启动可以更新。在 AppKit 中创建位图时传入空 planes 让框架分配内存，使用框架导出的颜色空间常量和空 PNG 编码属性字典。图标失败只影响显示。相同来源的历史记录共用图标。

密钥检测只匹配辨识度高的格式。熵值或助记词启发式检查容易让普通文本无故从历史中消失。

## 写入与自身复制

复制、粘贴和合并共用一把操作锁。写入前登记自身标记，等待文件授权期间持续有效，写入成功才开始计时，失败则清除。文本标记取纯文本哈希，因为监听器读回的可能是 HTML 的纯文本表示。文件标记取实际写回的路径列表。macOS 保留存储路径，其他平台按 arboard 的规范路径和过滤规则计算。

macOS 26 的粘贴板服务器会丢弃没有访问权限的文件 URL，即使 `writeObjects` 返回成功。ClipMan 先尝试打开文件以触发系统授权，再将 NSURL 直接写入 NSPasteboard，并核对读回的 URL 列表。这样能发现部分成功及授权被拒绝的情况。终端启动的进程可能继承终端授权，因此访达启动也是验证场景。

仅在写入成功后更新历史。合并时按选择顺序使用文本和文件路径，图片跳过并且不计作已使用。一次事务写入相同时间戳。写入之后的维护失败单独报告，避免用户重试并重复粘贴。手动复制同样遵循取用格式设置。

`globalPlain` 只有在内容通过过滤并保存后才清除系统剪贴板的格式。历史容量裁剪可以让新记录立即消失，这仍是一次成功的保存，但不能发出已不存在的列表项。即使存储时限制了 HTML 大小，核对系统内容时仍需完整 HTML。macOS 和 Windows 在写锁内比较系统序号，Linux 比较文件、文本和 HTML。Linux 无法区分外部应用再次复制完全相同的内容。

## SQLite 与数据所有权

记录使用带小数的 Unix 秒数。SQLite 同时读取旧整数和新实数。最近列表按时间戳与 ID 排序，索引和翻页游标共用这两个字段，避免同一时间的记录跨页丢失或重复。重复复制保留缺失的旧元数据，已有新值时更新。列表只返回至多两个各 4096 字符的路径及文件总数；文本摘要使用 Base64，缩略图使用 data URL。预览在 SQL 中限制大小，取用仍读取完整数据，合并无需读取跳过的图片原始字节。共用行解码器的查询须保持列顺序一致。

旧版本可能在降级期间向 v3 数据库写入换行格式的路径。每次打开时检查这些行并转换为 JSON；先建立所需列，再填旧值，完成索引重建后才写入新版本号。数据库损坏时将数据库及其 SQLite 辅助文件一起隔离，再在同一目录创建新库。其他打开错误终止启动。恢复通知通过回调传入，使存储测试可以独立于桌面运行。

启用增量回收需要一次完整 VACUUM。之后在删除事务提交后逐行读取增量 VACUUM 的结果，直到执行完毕。回收失败只记日志，已提交的删除仍然成功。

迁移期间从备份到替换连接一直持有存储锁，使等候中的采集写入新库。用独占创建的唯一文件测试目的目录的写权限，拒绝已有数据库的目录。升级备份另取唯一文件名，所以能安全删除本次产生的不完整备份。旧连接关闭后 Windows 才能清理旧库文件。

设置读取兼容旧版顶层键和值，保存时严格验证，并在写盘成功后更新内存。设置文件损坏时保留原文件并暂停采集。迁移独占数据路径，托盘独占暂停状态，二者与设置保存串行执行。重置和普通保存共用校验和回滚，均保留这两个字段。托盘读完数据库即释放锁，在后台执行可能与主线程互等的操作；新菜单构建完整后才替换旧菜单。
